# Deployment Guide

Three deployment targets are covered: **local reproduction**, **Streamlit
(Docker / Streamlit Cloud)**, and **PostgreSQL-backed production**.

## 1. Local reproduction (zero infrastructure)

```bash
git clone <repo-url> && cd decoding-customer-value
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt                        # or: pip install -e ".[all]"
python -m src.pipeline                                 # builds everything from the raw CSV
pytest -q                                              # 28 tests
```
Outputs land in `data/processed/` (clean data, feature table, SQLite DB) and
`reports/` (validation, profiling, loyalty framework, exec summary, SQL exports).

## 2. Streamlit app

### Local
```bash
pip install -e ".[dashboard]"          # streamlit + plotly
streamlit run src/dashboard/app.py
```
The app auto-runs the pipeline on first launch if the feature table is missing.

### Docker
```bash
docker build -t dcv-dashboard .
docker run -p 8501:8501 dcv-dashboard
# open http://localhost:8501
```

### Streamlit Community Cloud
1. Push the repo to GitHub.
2. On share.streamlit.io, create an app pointing at `src/dashboard/app.py`.
3. Set the Python version to 3.11 and add `requirements.txt` (the dashboard
   extras are included). No secrets are required for the SQLite default.
4. (Optional) add Postgres credentials as Streamlit **secrets** and set
   `DCV_DB_BACKEND=postgres` to back the app with a managed database.

## 3. PostgreSQL-backed production

```bash
# 1. Provision a database and user, then:
export DCV_DB_URL="postgresql+psycopg2://dcv_user:password@host:5432/dcv"
pip install -e ".[postgres]"

# 2. Build the analytics layer into Postgres:
python -m src.pipeline                  # loads table + applies all views

# 3. Point Power BI / Streamlit at the same database.
```
The `DatabaseManager` uses SQLAlchemy for Postgres automatically; the SQL view
files run unchanged. Schedule `python -m src.pipeline` (cron / Airflow / GitHub
Actions) to refresh on new data drops.

## 4. Configuration reference
All configuration is environment-driven (`.env` from `.env.example`):

| Variable | Default | Purpose |
|---|---|---|
| `DCV_DB_URL` | _(unset)_ | Full SQLAlchemy URL; overrides everything |
| `DCV_DB_BACKEND` | `sqlite` | `sqlite` or `postgres` |
| `DCV_STRICT_VALIDATION` | `true` | Abort pipeline on ERROR-severity data issues |
| `DCV_N_SEGMENTS` | `5` | KMeans cluster count |
| `DCV_THRESH_premium_value_percentile` | `0.80` | Premium cutoff |
| `DCV_RANDOM_SEED` | `42` | Reproducibility |

## 5. CI/CD
`.github/workflows/ci.yml` runs lint (ruff), format check (black), and the test
suite on every push/PR against Python 3.10–3.12, then executes the full pipeline
as a smoke test. See the workflow for the exact matrix.
